5. CURRENT RECOMMENDED TOPOLOGY AND ITS LIMITS

Candidate design:
- Real S-1608 on M-400 REAC A.
- Dedicated wired PC NIC on M-400 REAC B.
- M-400 in normal FOH operation as master.
- Computer emulates a slave and follows the console's sample clock.
- One Windows ASIO driver exposes both directions to FL Studio.
- Start at 48 kHz with 24-bit REAC audio.

Documented M-400 distinctions:
- REAC A and SPLIT/BACKUP share a REAC system.
- REAC B is a separate system.
- A and B can each address up to 40 incoming channels.
- A has eight freely assigned output-patchbay channels; B has forty.
- The A/SPLIT output composition includes stagebox inputs as well as the
  console's eight assigned outputs.
- Therefore SPLIT/BACKUP is not an independent bidirectional PC port.
- Input availability depends on the endpoint's announced inventory.
- The M-400 supports 44.1/48 kHz; newer REAC devices' 96 kHz capabilities do
  not establish M-400 support for that rate.

Separate three capacities:
1) REAC transport channels.
2) Physical S-1608 I/O: 16 analogue inputs and 8 outputs.
3) M-400 processing: 48 input strips.

For example, 16 live inputs plus 32 independent DAW return strips use all
48 input strips. Sixteen plus forty require 56, beyond that processing budget.
The interface cannot add console DSP strips. Forty bidirectional network
channels also do not automatically create forty insert points within existing
console channels. The documented external insert facility uses local console
I/O pairs.

7. PROTOCOL BASELINE TO VERIFY AGAINST THE CAPTURES

REAC is raw Layer-2 Ethernet with EtherType 0x8819, not IP/UDP.

For a normally framed, untagged Ethernet packet:
- Bytes 0-5: destination MAC.
- Bytes 6-11: source MAC.
- Bytes 12-13: EtherType 88 19.
- Bytes 14-15: little-endian sequence counter.
- Bytes 16-17: frame type.
- Bytes 18-49: 32-byte multiplexed control block.
- Byte 50 onward: audio.
- Last two bytes: C2 EA marker.

Under the inspected twelve-samples-per-channel format:
frame_length = 52 + 36 * channel_count, excluding FCS.
340 / 628 / 1492 bytes correspond to 8 / 16 / 40 channels.

Do not infer role from length. Do not assume every console frame is full width.
Parse capture link type, VLAN tags, capture/original lengths and stream identity.

Audio uses a pairwise 24-bit braid. For zero-based channel ch and sample s:
g = 3 * (s * width + (ch & ~1))
Even channel low/mid/high bytes: g+3, g+0, g+1.
Odd channel low/mid/high bytes: g+4, g+5, g+2.
Sign-extend bit 23. Physical input mapping is a separate question.

Common frame types:
0000: filler, still carrying audio.
CDEA: control plus audio.
CFEA: master announcement plus audio.
Historical split-related types exist; do not assume this corpus validates them.

Non-filler outer control checksum: sum of 32 bytes modulo 256 equals zero.
Complete DT1 inner checksum: covered address/data/checksum sum modulo 128 is zero.
Check lengths, fragmentation, destination and message semantics as well.

The inspected CFEA rate-class byte is control block[17], untagged frame byte 35:
0 -> 48 kHz; 1 -> 96 kHz; 2 -> 44.1 kHz.
Verify against observed cadence; twelve samples per packet imply
4000 / 8000 / 3675 packets per second respectively.

A 1492-byte full-width stream at 48 kHz occupies approximately 48.5 Mbit/s per
direction including ordinary Ethernet wire overhead. Full duplex has separate
directional capacity. Timing and clock discipline remain the difficult parts.

8.2 Source identities
M = 00:40:ab:c4:9c:0a, console-associated source.
S = 00:40:ab:c4:7c:09, stagebox-associated OR emulated source.

M emits master/configuration traffic. S advertises an S-1608-like inventory.
A source MAC does not prove physical origin, especially in this emulation project.
Only meres47 and meres50 expose both sources together.

8.3 Variable console frame width
M sends both 340-byte and 1492-byte frames. reac_tx_research3 is entirely
340-byte M frames, including master announcements and scene traffic.
Some recordings show repeated width changes and roughly 200 ms capture gaps.
Do not present these as proof of a stable full-width session.

8.4 Exact audio forwarding evidence
In meres47, 6908 complete non-silent upstream audio blocks matched downstream
slots 9-24 byte-for-byte. Other tested even-aligned starting positions did not
match. Example: upstream packet 19381 and downstream packet 19388.

Only upstream slots 1-4 carry nonzero data in that file; slots 5-16 are silent.
Thus the nonzero evidence supports wire slots 1-4 -> downstream 9-12.
The full block alignment does not independently verify twelve silent physical
inputs. Capture timestamp differences are not DAW round-trip latency.

This is consistent with the documented A/SPLIT composition, but the capture
position remains unconfirmed. It is not validation of the B-port return design.

8.5 Rate discrepancy
M advertises rate class 2 in meres47 and meres47-m400-s1608-1-2return.
A long run in the latter is approximately 3674.85 packets/s, consistent with
44.1 kHz under the twelve-sample format.
M advertises rate class 0 in meres50 and the earlier console research files.

S has long near-8000-packet/s runs in meres47-s1608-slave-1-2return and meres50.
In meres50, M simultaneously advertises 48 kHz. If these are the two ends of one
REAC segment, investigate a rate mismatch. Do not claim a physical ADC rate or
a definite root cause from packet count alone. Windows capture timestamps are
batched; their microsecond deltas are not reliable egress-jitter measurements.

8.6 Inventory/payload discrepancy
S advertises 16 inputs, 8 outputs, headamp base 32:
010300108200000202020202010103030303030300000000000000000000004c

It occurs 19 times in meres47 and 13 times in meres50.
meres47 has 628-byte S frames, consistent with the sixteen-input declaration.
meres50 has 340-byte S frames, corresponding to eight channels under the current
twelve-sample interpretation. Explain that discrepancy rather than copying it.

8.7 A specific control-record inconsistency
The following S control block recurs:
04030013000200fe0ff0410a000012120000030000007df70000000000000001

Outer record length = 19; declared SysEx length = 15.
The inspected grammar expects outer length = SysEx length + 5, hence 20.
There are 32 occurrences: 19 in meres47 and 13 in meres50.
First examples: packets 18555 and 98188 respectively.

Both checksums pass. The DT1 address is 00000300, not FreeREAC's captured
box-ready address 03020001. No complete SINGLE DT1 tag 0302 was found in this
corpus. Do not equate a record length or a variable named 0013 with readiness.
Do not change the address without understanding which message was intended.

8.8 Capture-header defects
29 records have four leading FF destination bytes where six are expected,
a Roland source MAC immediately afterwards, 8819 at raw offset 10 instead of 12,
and stored lengths 338/1490 instead of 340/1492. The C2 EA tail remains.
Counts: meres47 = 9; meres47-m400-s1608-1-2return = 2; meres50 = 18.
Example: meres47 packet 18969.

These were excluded from normal decoded statistics and listed as diagnostic
reconstruction candidates. Raw captures remain unchanged. Do not silently
prepend bytes or interpret the resulting apparent EtherTypes as real protocols.
This is different from the +2 trailing residue described in older public captures.

8.9 Role filenames and counter statistics
4Slave, 5Split and 6Master contain only S-originated broadcast filler at about
4000/s with contiguous counters over roughly ten seconds. They do not expose
three proven enrolment/mode transitions.

Some Kevero files contain large sequence jumps paired with capture gaps.
Simple whole-file rate or modulo-counter subtraction therefore misleads.
forward_gap_slots in the JSON is a diagnostic total, not certified wire loss.
